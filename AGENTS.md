# AGENTS.md

Guidance for any coding agent or contributor working in this repository.

## Project overview

FastLap is a Reddit-style social network for Formula 1 fans (Spanish-language UI). It combines forum-style communities ("subreddits") with an F1 data dashboard gated behind a paid Premium tier. Built with Next.js 16 (App Router), React 19, TypeScript (`strict: true`), Tailwind 3 + Shadcn UI ("new-york" style, slate base color), Prisma 6/Postgres (Neon), Auth.js v5 (`next-auth@beta`), Upstash Redis, UploadThing, and Stripe.

## Common commands

```bash
yarn dev               # start Next.js dev server
yarn lint              # eslint . (flat config)
yarn test              # vitest run
yarn build             # production build (also required before `start`)
yarn start             # run production build
npx tsc --noEmit       # type check (strict)
npx prisma generate    # regenerate Prisma client (runs automatically on `yarn install` via postinstall)
npx prisma migrate dev # apply schema migrations locally (the production DB was synced with `prisma db push`)
docker-compose up      # run the containerized app (standalone Next.js output, port 3000)
```

Yarn is the package manager (`yarn.lock`). Tests use Vitest (`yarn test`, `yarn test:watch`; config in `vitest.config.mts`, files `src/**/*.test.ts`); so far they cover only the F1 data layer in `src/lib/f1/`.

Linting uses ESLint 9 flat config ([eslint.config.mjs](eslint.config.mjs), `eslint-config-next` core-web-vitals + typescript) via `yarn lint` (`eslint .`). Errors fail the command; the new React Compiler rules (`react-hooks/set-state-in-effect`, `react-hooks/refs`) and `no-explicit-any` are set to warnings until the existing components are refactored. The Docker image builds on `node:22-alpine` (Next 16 needs Node 20.9+).

## Required environment variables

`.env` must define: `DATABASE_URL` (Postgres), `NEXTAUTH_SECRET` (Auth.js v5 also accepts `AUTH_SECRET`), `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `UPLOADTHING_SECRET`, `UPLOADTHING_APP_ID`, `REDIS_URL`, `REDIS_SECRET` (see `.env.example`). Stripe flows additionally need `STRIPE_SECRET_KEY` and `STRIPE_WEBHOOK_SECRET` (used in [src/app/api/webhook/route.ts](src/app/api/webhook/route.ts)). Self-hosted deployments (Docker, not Vercel) must also set `AUTH_TRUST_HOST=true` and `AUTH_URL` (replacing v4's `NEXTAUTH_URL`). Never commit real secrets.

## Architecture

### Auth and roles

- Auth.js v5 with Google provider, JWT session strategy, `@auth/prisma-adapter` ([src/lib/auth.ts](src/lib/auth.ts)). The file exports `handlers`, `auth`, `signIn`, `signOut`; `getAuthSession()` is `auth()` — use it in server components and route handlers. Auth.js v5 is still published only under the `beta` tag. The session cookie is `authjs.session-token` (`__Secure-` prefixed over HTTPS). On first sign-in, users without a username get one auto-generated via `nanoid(10)`.
- `UserRole` enum: `USER | ADMIN | PREMIUM` ([prisma/schema.prisma](prisma/schema.prisma)). Role is mirrored onto the session token via the `session` and `jwt` callbacks. The `jwt` callback only hits the DB at sign-in (when `user` is present), not on every request — so a role change is picked up only when the client calls `update()` from `useSession` (the `trigger === 'update'` branch re-reads role/username from the DB; note that `update()` with no argument only re-reads the cookie, so pass any payload, e.g. `update({ refresh: true })`, to run the callback). After a Stripe checkout, `success_url` is `/premium/success`, where `PremiumActivation` polls `update()` until the webhook has promoted the user.
- [src/proxy.ts](src/proxy.ts) (the Next 16 name for `middleware`, wrapped with Auth.js's `auth`) gates `/r/*/submit`, `/r/create`, `/settings`, and `/f1-dashboard/*` behind auth. **Premium is switched off** via the `NEXT_PUBLIC_PREMIUM_ENABLED` flag ([src/lib/features.ts](src/lib/features.ts), default off, read at build time): while off, the Premium card, `/premium`, `/premium/success`, `/api/checkout` and `/api/prices` are hidden (404) and every signed-in user can open `/f1-dashboard/*`. When on, `/f1-dashboard/*` requires `ADMIN` or `PREMIUM` and others are redirected to `/not-authorized`. Use `canAccessDashboard(role)` for that check. The Stripe webhook stays active.
- Stripe `checkout.session.completed` webhook ([src/app/api/webhook/route.ts](src/app/api/webhook/route.ts)) is the only path that promotes a `USER` to `PREMIUM` — there is no manual upgrade endpoint.

### Data model

The Prisma schema uses real database foreign keys (the former `relationMode = "prisma"` was removed) plus indexes on FK columns. Core models:

- `Subreddit` → `Post` → `Comment` (self-referencing via `replyToId` for nested replies)
- `Vote` and `CommentVote` are composite-keyed join tables (`[userId, postId]`, `[userId, commentId]`) with a `VoteType` enum (`UP | DOWN`)
- `Subscription` joins users to subreddits they follow

`Post.content` is `Json?` and stores EditorJS block data — never plain text. It is validated with a real EditorJS schema in [src/lib/validators/post.ts](src/lib/validators/post.ts). Use [src/components/EditorOutput.tsx](src/components/EditorOutput.tsx) to render it; rich post creation goes through [src/components/Editor.tsx](src/components/Editor.tsx).

### Redis: hot-post cache and rate limiting

- [src/app/api/subreddit/post/vote/route.ts](src/app/api/subreddit/post/vote/route.ts) caches a post into Upstash Redis as a `post:${postId}` hash once its net vote count reaches `CACHE_AFTER_UPVOTES` (currently `1`). The count is recomputed from fresh DB data after each mutation (`recountAndCachePost`); if it falls below the threshold the entry is dropped. Use `postCacheKey` / `invalidatePostCache` from [src/lib/redis.ts](src/lib/redis.ts) — the post delete endpoint invalidates too, so a deleted post can't be served from cache. The `CachedPost` shape lives in [src/types/redis.d.ts](src/types/redis.d.ts); any read path that consumes cached posts must be compatible with it.
- [src/lib/ratelimit.ts](src/lib/ratelimit.ts) defines `@upstash/ratelimit` sliding-window limiters: votes (10/10s), posts (5/min), comments (10/min). Apply them in any new mutation endpoint of the same kind.

### App Router layout

- Route groups: `(auth)` holds `/sign-in` and `/sign-up`. The `@authModal` parallel route slot ([src/app/@authModal/](src/app/@authModal/)) uses intercepting routes (`(.)sign-in`, `(.)sign-up`) to render auth as a modal over the current page; the root layout renders both `{children}` and `{authModal}` ([src/app/layout.tsx](src/app/layout.tsx)).
- `/r/[slug]` is a subreddit page; `/r/[slug]/submit` is the post-creation page; `/r/create` creates a subreddit.
- `/u/[slug]` is a user profile.
- `/f1-dashboard/` contains `clasificacion`, `pilotos`, `carreras` (calendar), `noticias` (still static sample content) sections (plus `piloto`, `carrera/[season]/[round]`, `noticia` detail routes). There is no sidebar: [layout.tsx](src/app/f1-dashboard/layout.tsx) shows [DashboardNav](src/components/f1-dashboard/DashboardNav.tsx), a scrollable row of pills (the active section is derived from the path), above the page.
- Vercel deployments are disabled for `claude/**` branches in [vercel.json](vercel.json).
- Other pages: `/premium`, `/faqs`, `/settings`, `/not-authorized`.
- **Next 16 async APIs:** `params` in pages and route handlers is a `Promise<{...}>` and must be awaited; `headers()` is async. Follow the existing pages as the pattern.

### API surface

Under [src/app/api/](src/app/api/):

- `auth/[...nextauth]` — NextAuth handler
- `posts/` (GET, paginated by `limit`/`page`; filters by `subredditName`, `username`, or the caller's followed communities)
- `subreddit/{post/{create,delete,vote,comment},subscribe,unsubscribe}` and `subreddit/[slug]`
- `users/[slug]`, `username/` (rename), `profile-image/`, `search/`
- `link/` (URL preview for EditorJS LinkTool; `isSafeUrl()` blocks private IPs and non-http(s) protocols to prevent SSRF — keep that check on any server-side fetch of user-supplied URLs), `uploadthing/` (image uploads — see [core.ts](src/app/api/uploadthing/core.ts))
- `checkout/` + `prices/` + `webhook/` — Stripe Premium subscription flow (Stripe API version pinned to `2024-04-10`)
- F1 data does not go through API routes: server components read it with `src/lib/f1` from [Jolpica-F1](https://github.com/jolpica/jolpica-f1), the drop-in successor of `ergast.com` (shut down after the 2024 season; base URL `https://api.jolpi.ca/ergast/f1`, overridable with `ERGAST_BASE_URL`, defined in [src/lib/ergast.ts](src/lib/ergast.ts)).

Request bodies are validated with Zod schemas in [src/lib/validators/](src/lib/validators/) (`post.ts`, `comment.ts`, `subreddit.ts`, `username.ts`, `vote.ts`, `piloto.ts`).

### F1 data layer (`src/lib/f1/`)

Typed, validated access to Jolpica-F1 for the rebuilt dashboard (see [docs/PLAN-DASHBOARD.md](docs/PLAN-DASHBOARD.md)). Server-side only; pages should call `queries.ts`, never the API directly.

- `client.ts`: `createF1Client()` — timeout, retries with backoff on 429/5xx/network errors (honours `Retry-After`), request spacing under the 4 req/s limit, `getAll` pagination (100 per page), Next.js `revalidate`.
- `schemas.ts`: Zod schemas that also convert Ergast's numeric strings to numbers. A response that does not match throws `F1SchemaError` naming the offending path.
- `queries.ts`: `getCalendar`, `getNextRace`, `getDriverStandings`, `getConstructorStandings`, `getRaceResults`, `getPitStops`, `getDrivers`, `getDriver`, `getDriverResults`. Path inputs (season, round, ids) are validated before they reach the URL. Closed seasons are cached for a week, the running one for an hour.
- Tests use **synthetic** fixtures in `__fixtures__/`. Real responses can be captured with `node scripts/capture-f1-fixtures.mjs` (needs internet) into `__fixtures__/real/`; `contract.test.ts` then validates the schemas against them.
- Migrated to this layer so far: the dashboard home (next race + top-5 standings), `/f1-dashboard/carreras` (season calendar) and `/f1-dashboard/clasificacion` (drivers/constructors championship per season with an accumulated-points chart) and `/f1-dashboard/carrera/[season]/[round]` (summary, classification with places gained and fastest lap, pit stops, standings after the race, previous/next race; a race not yet run shows its weekend schedule), all server components. Race helpers (`raceSummary`, `placesGained`, `groupPitStops`, `fastestPitStop`) are in `race.ts`. The chart (`PointsChart`, recharts, monochrome lines) is computed by `pointsProgression` from `getSeasonResults` + `getSeasonSprintResults` (results arrive 100 per page and a race can be split across pages: `mergeRaces` joins them); it can differ from the official table if a penalty was applied later. Pure calendar helpers (`weekendSessions`, `raceStatus`, `findUpcomingRace`) live in `calendar.ts`, date formatting in `format.ts`. Times are UTC in the API; `LocalTime` shows them in the viewer's time zone and `Countdown` ticks with `useSyncExternalStore` (no effects, no hydration mismatch).
- **Own copy of historical data (slice 6):** `snapshots.ts` makes the queries read-through over the `F1Snapshot` table (key `v<SNAPSHOT_VERSION>:<query>:<params>`, JSON payload of the already-parsed result). Only final data is stored: closed seasons (`isClosedSeason`) and race results older than 3 days; the running season, empty results and `null` never are. A DB failure falls back to Jolpica. Bump `SNAPSHOT_VERSION` when `schemas.ts` output changes. `sync.ts` (`syncSeason`) backfills a closed season; `GET /api/f1/sync?season=YYYY` (or `from`/`to`, max 3 per call) does it with `Authorization: Bearer $CRON_SECRET` (route off without the variable). Public read API: `GET /api/f1/<season>/<calendar|drivers|driver-standings|constructor-standings|results|sprint>`, closed seasons only, with the CC BY-NC-SA attribution in the body. Apply the schema with `prisma db push` (production has no migrations folder). Tests: `snapshots.test.ts` with an in-memory store; call `setSnapshotStore(null)` in tests that mock `fetch`.
- All dashboard pages that show F1 data now use this layer; there are no `/api/ergast/*` routes any more. `/f1-dashboard/pilotos` (season drivers with points, wins and podiums, filters) and `/f1-dashboard/piloto/[id]` (career stats computed from every race result: races, wins, podiums, starts from P1, fastest laps, points, retirements, teams, season by season, titles from the final standings of each season) use `driver.ts` (`statsOf`, `teamHistory`, `seasonLines`, `championshipYears`). Only the news section still uses hard-coded content.

### Design system ("Nothing" language, direction B)

Dark by default with a light theme (`<html data-theme="dark|light">`, set before first paint by an inline script in [src/app/layout.tsx](src/app/layout.tsx) and switched by [ThemeToggle](src/components/ThemeToggle.tsx), saved in `localStorage.theme`). Details and rationale: [docs/AUDITORIA-VISUAL.md](docs/AUDITORIA-VISUAL.md).

- **Tokens** live in [src/styles/globals.css](src/styles/globals.css) as RGB channels (`--background`, `--card`, `--muted`, `--border`, `--input` (the visible border), `--primary`, `--signal`, `--success`, …) and are mapped in [tailwind.config.ts](tailwind.config.ts) (`bg-card`, `text-muted-foreground`, `border-input`, `text-signal`, `text-display`, …). **Never hard-code colours** (`bg-white`, `text-gray-500`, `bg-red-500`) or use `dark:` variants: use the semantic classes so both themes work.
- **Fonts** (via `next/font/google`): Space Grotesk (`font-sans`, body), Space Mono (`font-mono`, labels) and Doto (`font-display`, dot-matrix). Use the `.label` class for small uppercase mono metadata (never for user-written text) and `.display` for headlines or big numbers, at most **once per screen**.
- **Rules:** the primary button is an inverted pill (white on black in dark); red (`signal`/`destructive`) is only for live status, errors and destructive actions, never decoration; no shadows or gradients (the dot grid, `.dot-grid`, is the one allowed motif); dividers only between identical items; `text-faint` (#666) is for decorative/disabled elements, not for text that must be read.
- Social screens (V2): `Post.tsx` is a card (preview via `src/lib/postPreview.ts`, `post-vote/VotePill.tsx`, actions in a `modal={false}` dropdown); the home feed shows `homepage/NextRaceModule.tsx` (null if Jolpica fails or takes over 4 s). Keep Radix dropdowns that open dialogs non-modal.
- **Race weekend hub (slice 7):** public page `/gp/[season]/[round]` (`force-dynamic`). `lib/raceHub.ts` has the pure rules (`dotdState`: "Driver of the Day" opens when the race ends and has results, closes 48 h later; `weekendStarted`; thread text; `tally`). `lib/raceThread.ts` (`ensureRaceThread`) lazily creates the weekend's thread as an ordinary `Post` by the system user (`sistema@fastlap.invalid`, username `fastlap`) in community `formula1` (created if missing), once the first session has started; `RaceWeekend` is unique per (season, round) so concurrent visitors get one thread. Votes: `POST /api/f1/dotd` (auth, `voteRatelimit`, one row per user and race in `DriverOfDayVote`, changing the vote overwrites; driver must be in the results). Component: `components/race-hub/DriverOfDay.tsx`. Linked from `NextRaceModule` and the dashboard race page. Route files must not export helpers: shared server code lives in `lib/dotd.ts`.
- **Prediction leagues (slice 8):** each community can open one `PredictionLeague` per season at `/r/<slug>/liga` (creator or ADMIN, via `POST /api/league/create`; rules: points per exact podium place, per podium driver in another place, per fastest lap, sprints on/off). Any signed-in user predicts the podium (+ optional fastest lap) of the next race, and of its sprint when the league includes them, with `POST /api/league/predict` (`voteRatelimit`; changeable until the deadline = start of qualifying / sprint qualifying, falling back to the session itself). **Points are never stored**: `lib/league.ts` (pure: `outcomeFromResults`, `scorePrediction`, `predictionDeadline`, `pickProblem`, `buildLeaderboard`) computes them on read from the season results (`lib/leagueData.ts` `loadOutcomes`), so a corrected result re-scores everything. Ties break on exact places and share the rank. Models `PredictionLeague`, `Prediction` (+ `PredictionKind`). UI: `components/league/{PredictionForm,LeagueCreateForm}.tsx`; use native `<select>` (styled globally).
- **Live timing prototype (slice 9, off by default):** `LIVE_SIMULATION=true` enables `/live` and `GET /api/live/stream` (SSE); without it both return 404. `lib/live/types.ts` is the provider-neutral `LiveState` (tower, status, race-control messages, `run` + `seq` for ordering); `simulator.ts` is a seeded simulated race with invented drivers (the only source: there is **no adapter for the real F1 feed**, whose terms were not checked, see PLAN risk R4); `hub.ts` (`LiveHub`) fans states out in-process, ticks only while someone listens and restarts the race after it ends; `components/live/LiveTower.tsx` is the client. It needs a long-lived Node process (Docker/standalone), not serverless, and one instance (several would each run their own source). Measure with `node scripts/measure-live.mjs <clients> <seconds> <baseUrl> <serverPid>`.
- **Notifications (in-app):** model `Notification` (`dedupeKey` unique per user makes generated ones idempotent). Comment events (`lib/notifications.ts` `commentNotifications`: post author + author of the comment replied to, never the actor, never twice the same person) are created in `api/subreddit/post/comment`. Time-based ones (prediction deadline within 24 h and no prediction yet; points for races of the last 14 days) are generated by `lib/notify.ts` `syncLeagueNotifications`, run in the background (`after()`) when the bell polls `GET /api/notifications/unread` (every 60 s), at most once per 10 min per user (Redis lock; if Redis fails it is skipped). `POST /api/notifications/read` marks one or all. UI: `NotificationBell` (Navbar), `/notificaciones`, `NotificationList`. Unread marks use the primary colour, not red. Email delivery is not implemented.
- **SEO (A2):** set `NEXT_PUBLIC_SITE_URL` in production (default `http://localhost:3000` would put localhost in canonical URLs and the sitemap). `lib/seo.ts` (`siteUrl`, `absoluteUrl`, `truncate`, `jsonLd`), root `metadata` (title template `%s · FastLap`, `metadataBase`, Open Graph, Twitter), `generateMetadata` on community (in its layout), post (description from `postPreview`, first https image as OG image), race hub and user pages, each with a canonical path. `app/robots.ts` and `app/sitemap.ts` (home, FAQs, communities, posts, started race weekends; a failing source only drops its entries). Share cards: `lib/ogImage.tsx` + `opengraph-image.tsx` at the root, community, post and race hub (plain fonts, no network). Structured data via `components/JsonLd.tsx`: `DiscussionForumPosting` on posts, `SportsEvent` on the race hub. Private or transient pages (sign-in/up, settings, notifications, Premium, `/live`, the whole dashboard, not-authorized) are `noindex` and disallowed in robots.
- **Moderation (A3):** any signed-in user reports a post or comment that is not theirs (`POST /api/reports`: reason SPAM/ABUSE/OFF_TOPIC/OTHER + optional details ≤300; one report per user and target via `targetKey`; limits 5/min and 30/day). UI: "Denunciar publicación" in the post's `⋯` menu (`ReportPostMenu`, non-modal dropdown) and "Denunciar" on comments (`ReportCommentButton`), both through `ReportDialog`. Admins (role `ADMIN` only) get `/admin/denuncias` (404 for anyone else, noindex, disallowed in robots, link in the account menu): one queue entry per reported target (`lib/moderation.ts` `groupReports`: most reported first), with `ModerationActions` → `POST /api/moderation/resolve` (`remove` deletes the content through `lib/content.ts` `deletePost`/`deleteComment` — also used by the normal delete routes — and notifies the author with a `MOD_REMOVED` notification; `dismiss` closes the reports). Every decision is kept in `ModerationLog` (reports themselves cascade away with the content). Not implemented: community-level moderators, auto-hiding at N reports, user bans/suspensions, appeals.
- **Prediction profile and global ranking (A4/A5):** `lib/profileStats.ts` (pure): `firstPredictionPerRace` (a user's first-sent prediction for each race counts, so predicting again in another league cannot hedge), `computeUserStats` (points, exact places, perfect podiums, best race, streak, average), `champions` (rank 1 with points), `GLOBAL_RULES` (= default rules, equal for everybody). `lib/predictionData.ts` (server) loads them: `loadGlobalBoard(season)` for the public page `/pronosticos?season=YYYY` (links: header on ≥sm, account menu, home page card) and `loadProfilePredictions(userId)` for `ProfilePredictions` on `/u/<name>` (failure there never breaks the profile). Badges are awarded only for finished seasons: global champion and winner of each league the user played. Points are still computed on read, never stored.
- **FAQs:** the public `/faqs` page and its `FAQPage` JSON-LD come from `src/lib/faqs.ts` (`FAQS`, `SUPPORT_EMAIL`); native `<details>`, server-rendered. Every answer must describe what the app does today (a test blocks known false claims): update it when a feature changes.

Results list is full-width and `fixed` on phones. The shared `Command` item uses `data-[disabled=true]:` — cmdk sets `data-disabled="false"` and the old `data-[disabled]:` made every item unclickable. On phones the theme toggle is the short mark `[◐]` so the search keeps room next to the bell.

Wrap a sideways-scrolling table in `components/ScrollRegion` (focusable, named). `text-faint` is decorative only; readable text uses `text-muted-foreground` or stronger. `--signal` is lighter in dark (AA as text) and its hover fill takes black text; success is darker in light. Card/section titles under the page `h1` are `h2`. Give a landmark a name that differs from any other landmark on the page. Re-run axe (axe-core via Playwright, both themes, 390 px and 320 px) after UI changes.
- **Performance and PWA (A9):** `src/app/manifest.ts`, icons in `public/icons/` (dot-matrix mark, regenerated from HTML if the logo changes), `viewport.themeColor`, `ServiceWorkerRegister` (production only) and `public/sw.js`: pages always from the network with `offline.html` as fallback, `/_next/static` and `/icons` cached forever, `/api/*`, other origins and non-GET never touched; bump `VERSION` in `sw.js` to drop old caches. `next.config.js`: `/sw.js` is `no-cache`, and `htmlLimitedBots: /.*/` keeps metadata in `<head>` (otherwise dynamic `generateMetadata` is streamed into `<body>`). Avoid layout shifts: reserve space for streamed or late content (`NextRacePlaceholder`, the 16:9 image box in `Post`), and never render a skeleton above content the server already sent (`PostFeed`). The Dockerfile has a `migrate` target (`prisma db push` one-shot), takes `NEXT_PUBLIC_SITE_URL` / `NEXT_PUBLIC_PREMIUM_ENABLED` as build args (they are inlined at build time), runs as non-root and has a `HEALTHCHECK` on `GET /api/health` (200 ok/degraded, 503 when the database is down). `scripts/check-env.mjs` validates the environment (also inside the image). They are drafts for a professional to review, not published pages, and contain `[PENDIENTE]` markers only the owner can fill. When a feature changes what data is collected, stored, shared or shown publicly (a new model with user data, a new third party, analytics, embeds, Premium), update the inventory and the affected drafts in the same change.
- **Legal-driven code changes:** post embeds (iframes) are not allowed — the editor has no Embed tool, `PostValidator` rejects `embed` blocks, and old ones render as a plain link (`CustomEmbedRenderer`); Google OAuth tokens are not stored (`stripProviderTokens` in the adapter's `linkAccount`; `scripts/scrub-google-tokens.mjs` cleans old rows). Before/after and how to revert: `docs/legal/CAMBIOS-TECNICOS.md`.
- Buttons are pills (`rounded-full`), cards use `rounded-lg`/`rounded-xl` with a border and `bg-card`.

### Client state and data fetching

- Global providers in [src/components/Providers.tsx](src/components/Providers.tsx): `SessionProvider` (NextAuth) wrapped in a `QueryClientProvider` (TanStack Query v5, `staleTime` 60s, `gcTime` 300s). Client components that mutate server state should use `useMutation` with optimistic updates — see [Editor.tsx](src/components/Editor.tsx) and the post-vote components in [src/components/post-vote/](src/components/post-vote/) for the established pattern.
- Pagination constant: `PAGINATION_RESULTS = 6` in [src/config.ts](src/config.ts).
- Date formatting: [src/lib/utils.ts](src/lib/utils.ts) exports `formatTimeToNow` with a custom Spanish locale (`hace 5m`, `justo ahora`, etc.) — use this instead of raw `date-fns` calls so wording stays consistent.
- `cn(...)` (clsx + tailwind-merge) is also in `utils.ts`.

### Prisma client singleton

[src/lib/db.ts](src/lib/db.ts) is marked `"server-only"` and stashes the client on `global.cachedPrisma` outside production to survive hot reloads. Always import as `import { db } from '@/lib/db'`. Never instantiate `PrismaClient` directly elsewhere.

## Conventions

- Path alias: `@/*` → `src/*` ([tsconfig.json](tsconfig.json)). TypeScript runs with `strict: true`; new and edited code must type-check without `any` shortcuts.
- User-facing text is in Spanish (toasts, errors, button labels). Keep this consistent in new UI.
- Shadcn primitives live in [src/components/ui/](src/components/ui/); feature components live alongside the page-level components in [src/components/](src/components/) (with `comments/`, `post-vote/`, `f1-dashboard/`, `homepage/`, `renderers/` subfolders).
- `uploadthing` / `@uploadthing/react` are still on v4 (peer-dependency warning for React 19; the helpers used are plain hooks). Moving to v7 is a separate migration: it replaces `UPLOADTHING_SECRET`/`UPLOADTHING_APP_ID` with a single `UPLOADTHING_TOKEN` and changes the router and `uploadFiles` APIs.
- ESLint rule `no-console` is `warn`: only keep `console.error` in legitimate `catch` blocks.
- Next image config whitelists `uploadthing.com`, `lh3.googleusercontent.com`, `utfs.io` ([next.config.js](next.config.js)) — add new external hosts there before using them.
- The build target is `output: 'standalone'` for the Docker image; don't switch without updating the Dockerfile.
- [docs/IDEAS.md](docs/IDEAS.md) is the bank of product ideas with their status (A = doable now, B = needs a decision, C = non-code); update it when one is done.
- [MEJORAS.md](MEJORAS.md) tracks the improvement backlog (done items are marked ✅); check it before proposing refactors and update it when you complete an item.
